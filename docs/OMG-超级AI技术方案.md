## 5. 调度器与心跳（OMGAIDispatcher.j）

（V2.0 骨架保留：心跳 tick / desire 竞选 / 硬规则状态 / 发呆看门狗。**V2.1 心跳增加两处**）

```vjass
function OMGAITick takes nothing returns nothing
    local integer i = 0
    local unit u
    loop
        exitwhen i > MAX_AI_UNITS
        set u = AIUnitTable[i]
        if u != null and UnitAlive(u) then
            if OMGAIHardState(u) then
                call OMGAIRunHardState(u)
            else
                call OMGAIAntiIdle(u)          // 发呆看门狗
                call OMGAISelectBehavior(u)     // desire 竞选
                call OMGAIRunBehavior(u)
            endif
            // V2.1：每 5 tick 调一次崩溃防护巡检（枚举数/递归深度/句柄水位）
            if ModuloInteger(i,5)==0 then
                call OMGAIGuardInspect(u)
            endif
        endif
        set i = i + 1
    endloop
    // V2.1：全局巡检（低频，1s 一次）——单位表水位、幻象/召唤物数量、日志水位
    call OMGAIGuardGlobalInspect()
endfunction
```

## 6A. 竞赛级战术意识（OMGAIStrategy.j）【V2.2 新增专章】

> 目标：**像比赛选手一样"懂"游戏**——不是看到就打，而是理解阵容、定位、时机、视野与针对。这是竞品没有的差异化优势。
> 设计原则：战术层**不改行为层代码**，通过给 desire 竞选注入"修正因子 + 高优通道"起作用——行为层照旧跑，战术层决定"什么时候该干什么、优先级加多少"。

### 6A.1 流派识别（Build Archetype）——对技能组合"理解透彻"

- **技能打标签**：SkillPool 配表为每个 OMG 技能打流派标签（位图）：
  - `物理位`：攻击力/攻速/暴击/吸血类（如 赏金忍术、剑舞）
  - `法术位`：魔法爆发/范围伤害/多重施法类
  - `控制位`：眩晕/沉默/减速/缠绕类
  - `生存位`：减伤/回血/魔免/位移逃生类
  - `功能位`：召唤/推塔/视野类
- **4+2 聚合评分**：英雄拿到 4+2 后，按标签累加 → 得出流派向量，取 max 归类：
  - **物理流**：物理位 ≥ 2 且无强控制 → 出装走攻击/暴击/攻速（§4.6 矩阵），团战定位"主力输出后排"；
  - **法核流**：法术位 ≥ 2 + 控制位 ≥ 1 → 出装走法伤/回蓝/减 CD，**多重施法组合优先生效**【坑#22 多重施法×潮汐黑名单除外】；
  - **肉盾流**：生存位 ≥ 2 或英雄模型 Tanker → 出装走血量/护甲/魔抗，团战定位"前排卖"；
  - **控制辅助流**：控制位 ≥ 2 → 出装走团队装/跳刀，团战定位"先手开团"。
- **出装联动**：流派 → 选择装备决策表的对应列（§4.6 position×近战/远程矩阵升级为 position×近战/远程×**流派** 三维）。
- **验收**：AI 按流派出装的完成率 ≥ 90%（如物理流 AI 20min 攻击装成装）。

### 6A.2 团战定位与站位（Role Positioning）——"肉在前卖，输出在后"

- **定位分配**（开局 + 团战前重算）：按 流派+职业 给每个 AI 英雄分配定位：
  - `VANGUARD`（前排）：肉盾流/Tanker → 团战站位靠前（距敌方主力 200~400），**先手开团/吸收伤害**；
  - `DPS`（中排）：物理流/Carry → 站在己方坦克身后，找最大输出角度（不站最前）；
  - `NUKER`（中后排）：法核流 → 卡施法距离边缘输出，**技能放完向后撤**（D2 放完技能补发原命令的战术版）；
  - `SUPPORT`（后排）：辅助/控制 → 保核心、交控、插眼，不进危险区。
- **站位实现**：OMGAIStrategy 团战前算好每个 AI 的"期望站位点"（相对己方阵型锚点的偏移），写入其目标缓存；行为层 Think 时优先走向站位点（高优修正）。
- **动态调整**：己方 VANGUARD 倒下 → DPS 前移补位；敌方主力消失 → 全线前压（配合 6A.4 蹲人）。
- **验收**：团战中 VANGUARD 承伤占比 ≥ 40%，DPS 死亡数 ≤ VANGUARD 的 1/2。

### 6A.3 秒人判定（Burst Kill）——"会秒人"

- **秒人判定**：`预估 5 秒爆发伤害（当前技能全 CD 就绪的爆发总和）≥ 目标当前血量 × 1.1` → 目标进入"可秒名单"。
- **秒人通道**：可秒名单非空时，给对应 gank/团战 desire **注入 +0.5 高优修正**，并锁定该目标为集火对象（OMGAITargetSel 的 focusTarget 强制覆盖）。
- **连招编排**：秒人时走 §6.5 TimedCombo（先控→爆发→补刀），且**不试探**（不先普攻暴露意图，直接进连招）。
- **冷却联动**：秒人判定只看"当前 CD 就绪"的技能，避免判了放不出来【坑#13】。
- **验收**：AI 单杀成功率 ≥ 60%（可秒名单触发后的击杀率）。

### 6A.4 关键英雄针对（Key Hero Targeting）——"蹲大哥"

- **关键英雄识别**：敌方威胁排序 top1（§8.1 净财富×0.3+输出×0.3+等级×0.4）= 敌方"大哥"，持续跟踪其状态（位置可见性/血量/CD）。
- **蹲守策略**（状态机）：
  - `大哥不可见`：AI **收敛自身暴露度**——不单独深入、不打无意义消耗、在小地图视野盲区待命（"他不出来，我躲后边"），同时布视野（§6A.5）找他；
  - `大哥出现`：立即向集火通道注入高优修正 + 通知最近队友（集结式单抓），秒人判定优先针对大哥；
  - `大哥残血`：全队转压，阻止其撤退/买活节奏【坑#19 追赶机制联动】。
- **反制大哥的装备/技能**：针对大哥流派反向配装（对面法核大哥 → 出魔抗/沉默针对；对面物理大哥 → 出护甲/缴械）【坑#20 情境出装升级为定向针对】。
- **验收**：AI 局中击杀敌方 top1 大哥的次数 ≥ 1.5 次/局，大哥死亡时 AI 在场率 ≥ 70%。

### 6A.5 视野博弈（Vision Warfare）——"开雾、插眼、反眼"

- **插眼**：§6.7 时间窗表保留；战术层升级——**围绕大哥活动区/野区入口布眼**（在 6A.4 的跟踪区布眼）。
- **反眼**：敌方插眼行为反演（敌方英雄在眼位附近停留/施放侦查技能 → 标记可疑眼位）→ 排队眼（排掉对方眼），优先级高于插己方眼。
- **开雾**：gank/秒人集结时，若己方有雾类道具（暗影护符/雾）→ **开雾接近目标**（雾中不可被预警），破雾即接秒人连招。
- **视野公平**：AI 遵循与玩家相同的视野规则（无透视作弊），只利用"插眼+反眼+雾"的合法信息战。
- **验收**：AI 队场均插眼数 ≥ 真人中位、场均反眼 ≥ 1 个、开雾 gank 成功率 ≥ 70%。

### 10.2 代码级崩溃防护清单（P1~P9）

## 11. 日志系统（OMGAILog.j）【V2.1 新增专章】

> 目标：**必要日志要留、崩溃可查、性能不崩**。三级通道：内存环形缓冲（§4.7）→ 本地写盘 → 服务器（KK 存档/上报）。

### 11.1 日志分级与节流

| 级别 | 内容 | 何时写 |
|---|---|---|
| DEBUG | 施法细节/走位计算 | 仅测试图（`-debug` 开关）【坑#15 后台日志——生产图禁止】 |
| INFO | 行为切换、gank 发起、团战触发、结算 | 可选（默认关，调参期开） |
| WARN | 数组越界拦截、句柄清理异常、模式未知 | 常开 |
| ERROR | 结算失败、必崩图自检失败、KK 写入失败 | 常开 |
| FATAL | 崩溃现场转储（§11.2） | 常开 |

### 11.2 崩溃现场转储（关键：崩了能查）

```vjass
// 触发：心跳巡检发现异常水位（句柄数暴增/枚举超限/单位表异常）或 ERROR 连续 ≥3 次
// 动作：
//  1) LOG_RING 最近 32 条 → gamecache（OMGAILog 存档，跨局保留）
//  2) AI 状态快照（各英雄行为/目标/血量/技能 CD + 单位总数 + 句柄水位）→ gamecache
//  3) 关键信息 → KK 服务器存档 key "OMGAI:crash:<时间戳>"（§12.3），玩家反馈时可后台查
//  4) 屏幕/聊天提示玩家"遇到异常请截图反馈"（可选）
// 对标竞品：B1069 崩溃日志发送工具 2.0（附玩家 ID/英雄/技能）——我们做同等能力且更全（含 AI 内部状态）
```

### 11.3 本地写盘通道（1.27 兼容，三条可并行）

| 通道 | 说明 | 适用 |
|---|---|---|
| Preload 机制 | 地图内 `PreloadGenClear/Start/End` 写文本到本地文件 | 最通用，无需平台；测试期用 |
| JAPI `DZ_WriteLog` | 第三方 japi 写日志能力（网易/KK 生态实证存在） | 需确认 1.27+KK 平台可用性，接入前验证 |
| gamecache | `SaveGameCache` 环形日志存档 | 崩溃后可回读，跨局保留 |

### 11.4 查询与上报

- **开发期**：`-log` 指令玩家可导出最近日志；测试图开 DEBUG 全量。
- **线上期**：WARN/ERROR 自动转 KK 存档（玩家匿名反馈即可查）；配合竞品式"崩溃日志发送工具"（可选做，先不做——优先做到不崩）。
- **调参**：§14 回归套件每次跑后读日志，自动比对 WARN/ERROR 计数（回归断言）。

## 12. KK 平台集成（KKAPI）【V2.1 新增专章】

> 事实（已核实）：KKAPI 是 KK 对战平台为 War3 提供的扩展 API，**兼容 DzAPI**（网易地图可直接迁移）；提供服务器存档 / 商业化 / 游戏模式和环境 / 玩家行为与信息 / 游戏内数据上报 / 轻量级服务端模块 / 多地图联动 / JAPI 八大类。文档：https://create.kkdzpt.com/kkapidoc/ ；开发者平台 https://create.reckfeng.com/ 。

### 12.1 用到哪些 KK API（按优先级）

| KK API | 用途 | 对应方案章节 |
|---|---|---|
| `DzAPI_Map_SaveServerValue / SaveServerArchive / StoreInteger/Real/Boolean / GetServerValue` | **自学习数据持久化**（替代/补充 gamecache） | §9 + §12.3 |
| `DzAPI_Map_GetPublicArchive / SavePublicArchive` | 全局公共存档（组合黑名单版本、排行榜） | §12.3 |
| `DzAPI_Map_Stat_SetStat` | **房间数据上报**：AI 胜率/MVP/技能命中率等，房间内展示 | §12.3 |
| `DzAPI_Map_GetMatchType` | **模式感知**：天梯/快速/房主模式 Key → OMGAIConfig 模式上下文【坑#30】 | §12.3 |
| `DzAPI_Map_GetPlayerInfo` 类 | 玩家身份/掉线判断（掉线接管【坑#23】辅助） | §5.3 |
| `KKApiEndBatchSaveArchive` | 批量存档收尾（结算原子性 P7） | §10.2 |
| JAPI / DZ_WriteLog 类 | 日志写盘扩展通道 | §11.3 |

### 12.2 平台接入前置

- 注册 KK 开发者平台 → 创建地图 → **上架前需上传测试服并通过审核，否则只能本地存档**（服务器存档能力受此限制）【KK】CSDN 实测文档。
- 本地开发用 `kkapi_local_plugin.ini` 模拟平台服务【KK】Gitee KKWE.md。
- 接入门槛列入 Phase 0 检查单：KKAPI 函数在本地能否编译（native 声明）+ 测试服联调。

### 12.3 对接设计

```vjass
// ① 自学习持久化（§9 bandit）：
//   key 规范：OMGAI:hero:<英雄名>:<技能ID>:<上下文特征串>
//   值：SCO|NBS|MIS（分号拼接字符串）
//   写入时机：每局结算 + 每 10 局强制（防丢失）；读取时机：开局加载
//   优点：跨平台服务器存档（玩家换机器也能续）——比 gamecache 强

// ② 房间数据上报（DzAPI_Map_Stat_SetStat）：
//   key: "omg_ai_winrate" / "omg_ai_mvp" / "omg_ai_hitrate" → 房间展示 AI 战绩
//   每局结束 SetStat(Player(0), key, 值)

// ③ 模式感知（DzAPI_Map_GetMatchType）：
//   GetMatchType() 返回值 → OMGAIConfig.matchMode
//   模式上下文驱动：车轮战换人规则【坑#30】/防守守塔【坑#18】/新手无加成【坑#21】

// ④ 崩溃/异常上报（§11.2 转储）：
//   FATAL/ERROR → SaveServerValue(Player(0), "OMGAI:crash:<tick>", 转储摘要)
//   玩家反馈时开发者后台可直接查，无需玩家传文件

// ⑤ 公共存档（SavePublicArchive）：
//   技能组合黑名单版本号、AI 难度全局配置 → 玩家侧无需手动更新配置
```

## 15. 风险与合规（V2.1 更新）

| 风险 | 说明 | 对策 |
|---|---|---|
| 许可证 | 多数调研仓库未声明/GPL | 全部"思想重写"；MIT（OpenHyperAI/LastOrder）可参考，保留出处 |
