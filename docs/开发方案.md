## 一、基图选择与理由

选择 `Dota 6.9 AI OMG_B376_11.w3x`（29MB）作为基图：

| 优势 | 说明 |
|---|---|
| 槽位正常 | w3i 结构标准（近卫 5 槽 num 1-5 + 天灾 5 槽 num 7-11），可直接设电脑 |
| 自带 AI 引擎 | 作者已实现完整电脑施法决策（SuijiAI 45 函数 + WNE/PEF 等事件回调） |
| 完整可玩 | 正常加载、正常开始游戏（B376_11 = 2026-08 版本，兼容 1.27） |

## 三、开发路径（混合架构）

### 3.1 总原则

**保留 Dota 6.9 的施法引擎（成熟），注入我们的竞赛级意识层（主动决策）。**

```
Dota 6.9 引擎（保留）
 ├─ SuijiAI 施法选择（蓝耗/冷却/目标/模板）
 └─ 技能/单位/物品数据（全部保留）
+ 我们注入（OMGAI 增强）
 ├─ 主动决策循环（周期遍历电脑英雄）
 ├─ 战术意识层（开雾/插眼/秒人/针对大哥/团战）
 ├─ 流派理解（物理/法师/肉）
 ├─ Guard 崩溃防护
 └─ Log + KK 日志上报
```

### 3.2 注入技术方案

1. **编译**：我们 OMGAI 库（vJASS 源码，12 个文件）用工程编译链（lua53 + jasshelper）编译成扁平 JASS 产物
2. **追加**：把产物（函数 + 全局变量）追加到 Dota 6.9 的 `war3map.j` 末尾
3. **激活**：在 Dota 6.9 `war3map.j` 的 main 函数末尾插入一行调用（启动我们的 AI 主循环）
4. **重打包**：复制 Dota 6.9 原图 → MPQEditor add 替换 war3map.j → 产物
5. **命名隔离**：我们库用 OMGAI_ 前缀，避免与基图函数/变量冲突

### 3.3 项目结构

```
D:\dota\DOTA69AI\
 ├─ src\              # 解包的研究文件（war3map.j/w3i/w3e/doo/w3a）
 ├─ scripts\          # 注入源码（OMGAI 库 + 接入脚本）
 ├─ logs\             # 编译/打包日志
 ├─ output\           # 产物地图（放 Maps\omg 测试）
 └─ build.bat         # 一键编译注入打包
```

### 6.2 真正根因（非基图版本）

inject_omgai.py main 末尾 5 个 ExecuteFunc 初始化调用中 4 个函数名错误：

| 错误调用名 | 正确函数名 |
|---|---|
| jasshelper__initstructs78298921 | jasshelper__initstructs78829546 |
| OMGAIGameMode___OnInit（3下划线） | OMGAIGameMode__OnInit（2下划线） |
| OMGAISkillData___Init（3下划线） | OMGAISkillData__Init（2下划线） |
| OMGAIInit___OnInit（3下划线） | OMGAIInit__OnInit（2下划线） |

ExecuteFunc 调用不存在函数 → 魔兽加载脚本失败 → 创建游戏弹回。与基图版本/地图大小无关。
